# agent.first — mode Cowork — plan de réalisation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** un mode Cowork où Gemini (site web) pilote le PC via Agent First
(lire/créer/modifier/supprimer des fichiers, chercher, lancer des commandes),
dans un dossier de travail choisi, avec analyse de sûreté et accord de
l'utilisateur pour les actions dangereuses, et affichage des étapes en direct.

**Architecture :** nouveau paquet `cowork/` (format d'action, analyse de sûreté,
exécution bornée au dossier, boucle d'agent) ; Agent First enchaîne les actions
dans la même conversation Gemini et pousse chaque étape à l'app par un flux SSE ;
l'app ajoute une bascule Chat/Cowork, un fil d'étapes et une carte d'accord.

**Tech Stack :** Python 3.13, FastAPI (`StreamingResponse` pour SSE), subprocess
PowerShell, sqlite3, Playwright (pilote v2), tkinter.filedialog (sélecteur de
dossier, dans un sous-processus), pytest ; app web HTML/CSS/JS (EventSource).

**Spec :** `docs/superpowers/specs/2026-10-16-cowork-design.md`

## Global Constraints

- S'ajoute à la v2 ; pilote, file d'attente, historique et app web sont gardés et étendus (pas réécrits).
- Playwright uniquement depuis le fil `file-gemini` ; une seule tâche Cowork à la fois (un seul Chrome dédié).
- Une action par message Gemini ; format : un unique bloc ```json `{"action": "...", ...}`. Actions : `lister`, `lire`, `chercher`, `creer`, `modifier`, `supprimer`, `commande`.
- **Bornage dur (décision de ce plan, au-delà de la fiche §4) : toutes les actions sur fichiers (`lister`, `lire`, `chercher`, `creer`, `modifier`, `supprimer`) sont refusées par le code si le chemin sort du dossier de travail — pas de contournement par accord en v1.** Seule `commande` peut atteindre l'extérieur, et c'est l'analyse de sûreté + l'accord qui la couvrent. Cela satisfait le critère 1.5 (« ne peut pas écrire/supprimer hors du dossier sans accord ») en l'interdisant tout court.
- Analyse de sûreté prudente : `supprimer` et toute commande non reconnue = dangereuse (accord requis). Liste des motifs dans un seul fichier (`cowork/surete.py`).
- Textes utilisateur en français. Chemins relatifs au dossier de travail.
- Git : chaque tâche commitée puis `git push` sur `main`. Commit terminé par `Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>`. Ne jamais commiter `donnees/`, `journaux/`, `profil-chrome-gemini/`, `style to copy.png`.
- `config.py` : `DELAI_COMMANDE = 120.0`, `MAX_ETAPES_COWORK = 40`, `TAILLE_MAX_SORTIE = 8000`, `ECHECS_FORMAT_MAX = 3`.

## Review Focus

1. **Chemin qui sort du dossier** (`../`, absolu) sur une action fichier : refusé par le code, pas seulement signalé → `test_resoudre_refuse_hors_dossier` (tâche 3).
2. **Gemini met du texte autour du bloc JSON, ou plusieurs blocs** : le premier bloc d'action valide est lu, le reste ignoré → `test_lire_action_ignore_le_texte_autour` (tâche 1).
3. **Commande non reconnue** (ni sûre connue, ni motif dangereux listé) : traitée comme dangereuse → `test_commande_inconnue_dangereuse` (tâche 2).
4. **Refus d'un accord** : l'action n'est pas exécutée, Gemini est informé et la boucle continue → `test_refus_continue_la_boucle` (tâche 4).
5. **Gemini n'émet jamais de fin** (boucle sans terme) : arrêt à `MAX_ETAPES_COWORK` → `test_limite_d_etapes` (tâche 4).

### Task 2 : Analyse de sûreté (`cowork/surete.py`)

**Files :**
- Create : `cowork/surete.py`
- Test : `tests/test_surete.py`

**Interfaces :**
- Consumes : `cowork.format.Action`
- Produces :
  - `@dataclass(frozen=True) class Verdict: dangereuse: bool; raison: str = ""`
  - `classer(action: Action) -> Verdict` : `supprimer` → dangereuse (« suppression définitive ») ; `commande` → `analyser_commande(action.champs["texte"])` ; autres → `Verdict(False)`.
  - `analyser_commande(texte: str) -> Verdict` : si un motif de `MOTIFS_DANGEREUX` correspond → dangereuse avec sa raison ; sinon si le premier mot (sans casse) est dans `COMMANDES_SURES` → `Verdict(False)` ; sinon → dangereuse (« commande non reconnue »).

`boucle.executer` (algorithme, car non déterminé par la signature) :
```
message = message_initial
echecs = 0
pour _ dans range(max_etapes):
    reponse = envoyer(message)
    action = lire_action(reponse)
    si action est None:
        si est_termine(reponse): emettre({"type":"termine","resume":reponse}); return
        emettre({"type":"erreur_format"}); echecs += 1
        si echecs >= echecs_max: emettre({"type":"termine","resume":"format non compris, arrêt"}); return
        message = "Format non compris. " + mode d'emploi court; continue
    echecs = 0
    emettre({"type":"action","action":action.nom,"champs":action.champs})
    verdict = classer(action)
    si verdict.dangereuse:
        emettre({"type":"demande","action":action.nom,"raison":verdict.raison})
        si non demander_accord(action, verdict.raison):
            emettre({"type":"refus"})
            message = formater_resultat(False, "Action refusée par l'utilisateur."); continue
    resultat = executer(action)
    emettre({"type":"resultat","ok":resultat.ok,"corps":resultat.corps,"diff":resultat.diff})
    message = formater_resultat(resultat.ok, resultat.corps[:taille_max])
emettre({"type":"limite"})
```
